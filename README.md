# 心情树洞 · Mood Hollow

> 一棵有大洞的树，一群萦绕不散的萤火虫。
> 把那些在人前说不出口的苦闷投进树洞，它会化作一只萤火，替你在夜里亮一会儿；
> 你也可以点开别人的萤火，只送上一个抱抱 —— **不能评论，不能回复，不能追问**。

为解答现代青年日益严重的心理问题尽一份力：让脆弱的情绪有一个容身之所，让心里的创伤被一个个陌生的善意治愈。

## 快速开始

**方式一：直接打开（最简单）**

双击 `index.html`，或拖进浏览器。零依赖、零构建、不需要联网。

**方式二：本地起个服务（推荐，localStorage 行为与线上一致）**

```bash
node tools/serve.js            # 默认 http://127.0.0.1:8123/，同时监听局域网
node tools/serve.js 8080       # 换端口
node tools/serve.js --local    # 只监听 127.0.0.1
```

**方式三：手机扫码打开**

```bash
node tools/serve.js                                    # 启动后会打印手机可用的地址
python tools/qr_tool.py http://<你的局域网IP>:8123/     # 生成二维码 PNG + 终端二维码
```

手机与该电脑连同一个 Wi-Fi，扫描 `qr-phone.png` 即可打开。

> 打不开多半是 **Windows 防火墙**拦了入站连接：在弹窗里允许 Node.js 通过「专用网络」。
> 如果手机和电脑不在同一网段（比如电脑在 `10.x` 而手机在 `192.168.x`），局域网这条路走不通，
> 需要用下面的"公网"方案。

**方式四：公网链接（任何人都能点开）**

这个项目是**单个 HTML 文件、无后端**，所以丢到任何静态托管上都能直接用：

- **GitHub Pages**：新建仓库 → 上传 `index.html` → Settings → Pages → 选分支 → 得到 `https://<用户名>.github.io/<仓库>/`
- **Vercel / Netlify**：把包含 `index.html` 的目录拖进去，几秒后给一个 `https://xxx.vercel.app` 链接
- 拿到公网地址后，二维码这样生成：`python tools/qr_tool.py https://你的地址/`

拿到公网链接后，任何人、任何设备都能点开或扫码，不要求同一个 Wi-Fi。

支持所有现代浏览器（Chrome / Edge / Safari / Firefox），手机端已适配竖屏与横屏。

## 交互

| 你想做的事 | 怎么做 |
| --- | --- |
| 把心事倒进树洞 | 在底部输入框写下来，按 `Enter`（`Shift+Enter` 换行）或点「投入树洞」 |
| 听一个陌生人的心事 | 轻轻点一下空中的萤火虫 |
| 送一份安慰 | 在展开的卡片里选一个动作：🫂 抱抱你 / 🤍 摸摸头 / ✨ 我懂 / 🌙 陪你一会儿 |
| 关掉卡片 | 点 `✕` 或按 `Esc` |
| 想找专业帮助 | 点右下角 `?` |
| 回看我投过的心事 | 点树上的**鸟巢**，或点右下角「🪹 我的心事」 |
| 换个季节 | 点右下角「❄ 冬天的秃枝」按钮，四季轮换 |
| 天气 | 点右下角天气按钮：冬天在 **晴 ↔ 雪** 之间切，其它季节在 **晴 ↔ 雨** 之间切 |

> 天气与季节是**正交**的：春夏秋可以下雨，冬天可以下雪；**雪只在冬天成立**（在别的季节点雪会被拒绝，离开冬天时雪会自动换成雨，回到冬天再还给你）。
> 冬天还有一件事不一样：萤火虫不飞了，它们会爬进树洞，蜷成一枚枚**蛹**过冬（点树洞能唤出一枚来看）。开春它们会重新飞出来。

**投递之后会发生什么**

1. 输入框里升起一只新的萤火虫，带着你写下的话飞向树洞；
2. 到了洞口它会缩进去、消失，洞沿荡开一圈光晕；
3. 过一会儿，树洞会把它重新吐回夜空 —— 这一次它身上没有任何身份，只是众多萤火中的一只，**在等一个陌生人点开它**。

被点开、被送抱抱的萤火虫会短暂地亮一下。你给出的每一次安慰，都会记在那只萤火虫身上。

### 鸟巢：我投过的心事都在这里

心事投进树洞之后，**树上会多一个鸟巢**——它是留给"我自己"的角落。点它（或点右下角「🪹 我的心事」）就能回看：

- **每条心事被关心了多少次**：四种安慰分别列出，例如 `🫂 12　🤍 7　✨ 3　🌙 5`
- **谁是此刻正在夜空里飞的那一条**：绿色小圆点标出来，点「去看看它」就跳回夜空、把那只萤火虫圈出来
- **搜得到**：输一句话里的几个字就能筛出那一条
- **排得了**：最新 / 最受关心 / 最早三种排法
- 鸟巢本身也会**被关心得越多越暖**：里面的蛋形亮光会跟着亮起来

> 为什么是鸟巢而不是树洞：树洞承担的是"投出去、放下"的隐喻，再让它当"回看入口"会语义打架；
> 而鸟巢在自然界里就是"攒起来、孵化、被照顾"的地方。

## 界面与视觉

- **树**：程序化生成的骨架模型（实测 87 根枝 / 约 2600 个轮廓顶点）。每根枝是一串带半径的中轴点，描边时沿法线偏移半径围成有体积的轮廓多边形——不是"沿路径堆圆点"，所以枝条有平滑的长细比和自然的弧度，树梢会向上收。
- **风**：树会动。按枝条层级给不同摆幅（树干几乎不动、树梢最明显，最大约 4.7% 树高），再叠一个缓慢的阵风包络，所以摆动有轻重缓急，而不是机械地左右晃。
- **光照**：整棵树先画成一张离屏蒙版，再用「本体 减去 反向平移的本体」取出**朝光的那道月牙边**——朝树洞的一侧是暖光，背侧是冷月光。这样树是剪影加体积，不会糊成一团灰。树干另有纵向树皮纹理。
- **季节**：冬（秃枝）/ 春（新芽 340 片叶）/ 夏（浓荫 460 片叶）/ 秋（金黄 420 片叶），由同一棵骨架换配色与叶子。叶子贴着枝条外半段生长并随风各自摆动，树冠另有一层柔光团把叶子聚成"冠"而不是散点。首次进入按当前月份自动选，也可以点右下角按钮切换，选择会被记住。
- **萤火虫的聚散**：它们不是永远平均铺在画面上，而是在"散开"与"聚拢"之间来回呼吸（散开 10~24 秒 / 聚拢 6~14 秒），每只的节奏各不相同，所以看起来是一群虫而不是一支队列。实测横向分布标准差：分散时约 145~214px、聚拢时约 53~81px（画布 1440px）；聚拢时最密的一小片能挤下 15 只，分散时最多 9 只。
- **雪**：冬天下雪时天色更沉，雪花比雨慢得多、被风明显吹偏，分远近两层画出景深。**积雪**与天气无关，整个冬天都在：枝上取每根枝朝上的那条边铺一层白（细枝挂不住雪就不铺），地面是一条起伏的雪被加一层淡淡的冷光和亮晶。
- **冬蛹**：入冬后萤火虫不再飞，它们会沿一条小小的抛物线爬进树洞，蜷成一簇呼吸式明灭的暖色蛹——像树洞替你把这些心事收着。开春全部苏醒、重新飞回夜空。季节往返不会弄丢任何一只。
- **树洞**：被岁月啃出来的不规则洞口（贝塞尔轮廓），一层层往里收成深黑，内壁带湿润反光，洞口外缘透出一圈暖光——它是画面的视觉中心。
- **性能**：树的蒙版与光影都是每帧重算的离屏合成，实测量级约几毫秒/帧，60fps 无压力。

## 功能一览

- 程序化生成的一棵大树与天然树洞（Canvas 2D 绘制，没有用任何图片素材）
- 会随风摆动的枝叶 + 四季可切换（冬/春/夏/秋）+ 晴 / 雨 / 雪 三种天气
- 冬天会积雪（枝上 + 地面），萤火虫会入洞成蛹，开春再出来
- 萤火虫群：各自巡游、呼吸式明灭、可被点中；被树洞吸收 / 从树洞新生都有独立动画
- 心事投递 → 匿名化 → 回流成萤火虫的完整闭环
- 匿名详情卡片：随机编号署名（如「第 1809 只萤火虫」）、模糊化的时间感（「3 小时前路过这里」）
- 四种安慰动作（🫂 抱抱 / 🤍 摸头 / ✨ 我懂 / 🌙 陪你）**各自独立计数**，
  分别显示在卡片顶部与各自的按钮徽标上；**同一次查看里同一个动作不会重复计数**
- 老数据兼容：过去只有"被抱过多少次"一个总数的记录，载入时会按内容哈希
  **确定性地拆成四种动作**——数字不丢，也不会每次打开都变
- 首次进入自动铺入一批真实质感的种子心事，夜空不会是空的
- 数据只存本机 `localStorage`，不上传、不联网、无账号
- 全站只有一个文本输入框（投递心事那个），从源码层面杜绝"评论区"
- 适配 `prefers-reduced-motion`、`env(safe-area-inset-*)`（刘海屏底部留白）
- 内置全国心理援助热线入口
- 六种屏幕尺寸下都保证「树洞在输入框之上」，矮屏自动切紧凑布局（有回归断言兜着）

## 为什么是"只能安慰，不能评论"

这是本项目的核心伦理选择，不是功能缺失。

- **评论会把树洞变回广场。** 一旦可以回复，投稿的人就会开始预判别人的反应，真话会重新被咽回去。
- **匿名 + 不可回复 = 安全的表达。** 说出来不需要承担任何社交后果，这是"容身之所"的前提。
- **善意应该是不求回报的。** 你不能追问对方是谁、后来怎么样了，你只能给一点温度 —— 这恰好是陌生人之间最珍贵的那部分。
- **不鼓励沉溺。** 因此没有排行榜、没有连续签到、没有"被安慰次数"的炫耀；只有一只萤火虫安静地亮着。

如果你或你身边的人正处在难熬的阶段，右下角 `?` 里有可以打通的电话。**会有人接的。**

### 关于二维码

现场没有可用的二维码库（`qrcode` / `cv2` / `pyzbar` 都没有），所以 `tools/qr.py` 是**从头实现**的：
字节模式编码 → Reed-Solomon 纠错 → 分块交织 → 矩阵布置 → 8 种掩码择优 → format 信息 → PNG。

为了确认它真的能被扫（而不是"看着像"），`tools/qr_verify.py` 做了**独立的逆向解码**：

1. 从 PNG 按定位图形还原模块矩阵
2. 读两份 format 信息并互相校验（必须一致）
3. 去掩码、反交织，对每一块算 **RS 伴随式**（必须全零）
4. 解析模式 / 长度 / UTF-8 文本，与期望字符串逐字比对

```bash
python tools/qr_tool.py http://10.0.0.5:8123/ .preview/qr-phone.png
python tools/qr_verify.py .preview/qr-phone.png http://10.0.0.5:8123/
```

这套校验在开发中确实抓到了一个真 bug：我最初把两份 format 信息的**位序与坐标顺序都排错了**
（读回来是 `0x4579` / `0x4F51`，正确应为 `0x45F9`），当时矩阵"看起来完全正常"，
只有逆向解码才能发现。

`index.html` 内部分区（按注释检索）：

1. 基础工具（可复现随机数、缓动、视口）
2. 精灵预渲染（萤火辉光、星点，避免逐帧建渐变）
3. 内容与存储（种子心事、`localStorage`）
4. 萤火虫（状态机：`float` / `absorb` / `respawn` / `pupa`）
5. 粒子与特效（涟漪、文字、安慰粒子）
6. 绘制（夜空 / 地面 / 树 / 树洞 / 萤火 / 粒子）
7. 心跳（吸收与回流的节奏）
8. 交互（点选、详情卡片、安慰动作）
9. 投递
10-13. Toast / 帮助 / 尺寸 / 主循环 / 调试钩子 / 启动

## 开发与自测

```bash
node tools/test.js                 # 逻辑与布局回归（156 项，跑完约 4 分钟）
node tools/diag.js                 # 逐帧打印状态（风、聚散、雨雪等）
```

> ⚠️ `tools/preview.py`（离屏渲染预览）**已损坏且不再维护**。
> 事故原因：我用 PowerShell 的 `Get-Content | Set-Content` 去批量同步参数，
> 它以 ANSI 读写，把文件里 95 处中文字节按**不可逆**方式替换成了 `?`，Python 无法再解析。
> 同一批操作还给 `tools/test.js` 加过 BOM（已修复），并最终把它也弄坏过一次（已重写为干净版本）。
> **成品 `index.html` 全程未被这条路径碰过**，编码与语法校验均通过。
> 仓库里的 `.preview/*.png` 是损坏前生成的，比现在的版本少了雪、冬蛹，叶子也更稀。
>
> 教训：**不要用 PowerShell 的文本 cmdlet 读写含非 ASCII 的文件**；
> 要么显式 `-Encoding utf8`，要么交给 Python / Node。

`test.js` 用最小 DOM + Canvas 桩件在 Node 里**真实执行页面脚本**，覆盖：

- 启动、尺寸、树洞位置与可见性
- 萤火虫运动（无 NaN、不出画、数量受控）
- 投递闭环：写入历史池 → 新萤火虫 → 被吸收 → 重新回流
- 点击看心事：署名匿名化、面板内容、关闭
- "不能评论"：动作按钮数量、无任何文本输入控件、文案存在
- 安慰计数：+1、同次查看不重复刷、不同动作可分别送
- 持久化与重启恢复（自己投过的心事会优先回到空中）
- 边界：空白不投递、500 字上限、六种屏幕尺寸下树洞不被输入框遮挡

`.preview/*.png` 是 Pillow 按同一套几何与配色公式复刻的离屏渲染，用于在没有无头浏览器的环境里核对构图。
现在这份预览图已经过期（是损坏前生成的），**以 `index.html` 的实际效果为准**。

## 隐私

- 没有任何网络请求、没有埋点、没有账号体系
- 心事只存在浏览器 `localStorage` 的 `mood-hollow/v1` 里
- 记录里只有：文本、时间戳、被抱抱次数 —— 没有 IP、没有设备信息、没有身份字段
- 清除浏览器数据会一并清除；换设备不会同步（这也是当前原型的诚实边界）

## 可以往下走的方向

1. **真正的跨设备匿名**：一个极简后端（只存匿名心事 + 计数），投递后立即脱敏，服务端不落任何可关联信息
2. **内容安全**：高风险表达（自伤/自杀意念）识别与温和的求助引导，但不做封禁、不做审查式拦截
3. **无障碍**：为萤火虫提供键盘可达的列表视图，给屏幕阅读器一条不必"点光点"的路径
4. **轻量寄托**：不引入成瘾性机制的前提下，允许"明天再来看看那只萤火虫"
5. **页面内显示二维码**：目前二维码是离线生成的 PNG，可以把它搬进页面，方便随手分享
